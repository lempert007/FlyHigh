How FlyHigh Plans Your Drone's Altitude

A plain-English walkthrough of the 9-step altitude algorithm in core/altitude.py

What the algorithm produces

Drone flight path
Takeoff / Return home
Min AGL floor
Max AGL ceiling
Ramp start point
Terrain pin (ramp safety)
Zone crossing
Home / Land

The 9 steps — grouped by what they do

🛫 Preparation (Steps 1–2) 📐 Planning (Step 3–4) 🎯 Selection (Step 5–6) 🔧 Build output (Steps 7–8) ✅ Verification (Step 9)
1
Resolve takeoff altitude
Decide how high the drone is at the moment it takes off.

If the user pinned a fixed altitude, use that. Otherwise, read the terrain elevation at the home point and add the minimum AGL clearance on top — the lowest safe starting height.
Preparation
2a
Insert zone-crossing points
Each POI area can have its own altitude rules (e.g. "fly lower here"). Whenever the route crosses into or out of a POI zone, a hidden waypoint is inserted at that exact boundary.

This ensures no single flight leg ever spans two different rule-sets at once.
Preparation
2b
Split impossible legs
Sometimes terrain varies so wildly on one leg that no single flat altitude can satisfy both "stay above the peak" and "stay below the ceiling".

The leg is split at its midpoint and each half is checked again — up to 3 times (making at most 8 sub-legs). After that a violation is logged.
Preparation
3
Compute floor & ceiling per leg
For each leg the terrain is sampled at 20 m intervals.

Floor = highest terrain point + min AGL — the drone must be at least this high.
Ceiling = lowest terrain point + max AGL — the drone must not exceed this.

Step 2b guarantees floor ≤ ceiling for every leg.
Planning
4
Propagate climb-rate limits
The drone can't teleport — it climbs and descends at a limited slope. Step 4 runs 4 fast passes over the leg list to tighten each leg's allowed altitude range so that every transition is reachable:

• backward & forward floor passes — "start climbing early enough"
• backward & forward ceiling passes — "start descending early enough"
Planning
5
Select cruise altitude
A single forward sweep assigns one altitude to each leg. The rule is simple:

Keep the current altitude unless forced to change.

The drone only climbs when the floor rises above it, and only descends when the ceiling drops below it. Fewer changes = smoother, more efficient flight.
Selection
6
Clamp takeoff altitude
Now that the first leg's cruise altitude is known, the takeoff altitude from Step 1 is bumped up if it would be too low to reach the first leg's floor in time.

(Only applies when the user hasn't pinned a fixed takeoff altitude.)
Selection
7
Insert ramp waypoints
Between any two legs at different altitudes, a ramp start point is inserted within the preceding leg. The drone flies flat, then begins climbing or descending at the exact moment needed to arrive at the new altitude right on time.

Because Step 4 already guaranteed the slope fits, no backwards walking is required.
Build
8
Terrain pins on ramps
During a ramp the drone's altitude is interpolated linearly. A hill hidden mid-ramp could be clipped even if the endpoints are fine.

Step 8 samples every ramp segment and, if the worst clearance violation is found, inserts a terrain pin waypoint there. This repeats until the ramp is clean.
Build
9
Final safety check
Every segment in the completed route is sampled at 20 m intervals one last time.

Any point where the drone would be below min AGL is a hard violation.
Any point where the drone would be above max AGL is a soft warning.

Violations are reported in the results panel but never block the download.
Verification

🔒 Key guarantees after all 9 steps

  • Every flat leg is within the min–max AGL band.
  • Every altitude transition respects the drone's max climb/descent rate.
  • Every ramp segment has at least min AGL clearance (via terrain pins).
  • Where constraints are physically impossible, a violation is logged — the route is still delivered.

API Layer — backend/api/

backend/api/plan.py
Planning Pipeline
Orchestrates the full mission plan: assembles the route, runs the altitude planner, executes safety checks, and packages the ZIP response.
  • plan_route(request)
  • _expand_maneuver_latlon(poi, ...)
  • _build_violations(violations)
backend/api/upload.py
Terrain Ingestion
Accepts GeoTIFF uploads, reprojects them to UTM via rasterio, and stores open DatasetReader handles in the session store.
  • upload_files(files, file_types)
backend/api/altitude_edit.py
Manual Altitude Edit
Accepts manually adjusted waypoint altitudes from the editor UI and re-runs only the safety checks, returning an updated violation list without replanning.
  • altitude_edit(request)
backend/api/missions.py
Mission CRUD
Reads and writes mission state (route + config) to JSON files on disk under backend/missions/.
  • list_missions()
  • get_mission(folder)
  • save_mission(folder, body)
  • delete_mission(folder)
backend/api/pdf.py
PDF Report
Generates an on-demand PDF report from the last plan result. Sections: summary stats, coverage, violation tables per category, altitude profile charts.
  • generate_pdf(request)
backend/api/settings.py · presets.py · terrain.py
Config Endpoints
Serve global user settings (GET/POST), built-in drone presets, and the list of pre-loaded GeoTIFF files from the terrain library folder.
  • get_settings() / save_settings()
  • get_presets()
  • get_terrain_library()

Core Layer — backend/core/

backend/core/altitude.py
Altitude Planner
The heart of FlyHigh. Runs the 9-step altitude planning algorithm: resolves takeoff, inserts zone crossings, computes leg bands, propagates climb limits, selects cruise altitudes, and inserts ramp + terrain-pin waypoints.
  • plan_altitude(legs, params, terrain)
  • _insert_zone_crossings(legs)
  • _propagate_climb_limits(legs)
  • _insert_ramp_points(legs)
  • _insert_terrain_pins(ramp, terrain)
backend/core/poi.py
Scan Pattern Generator
Generates boustrophedon (lawnmower) sweep strips for rectangular and custom-polygon POI areas. Supports transposed (warp-weft) passes. Entry corner is chosen to be closest to the previous waypoint.
  • generate_lawnmower_pattern(...)
  • generate_lawnmower_polygon_pattern(..., prefer_start)
backend/core/route.py
Route Assembly
Converts the user's sparse keypoints (start, waypoints, POI patterns, RTH) into an ordered flat list. Handles entry bearings for rectangular scans.
  • assemble_route(start, waypoints, pois)
  • compute_entry_bearing(prev, poi)
backend/core/terrain.py
Terrain Index
Reprojects a GeoTIFF to UTM and builds a RegularGridInterpolator over it. Provides point-sampling used by every other module. Out-of-bounds queries return NaN (graceful degradation).
  • TerrainIndex(dataset, zone_str)
  • TerrainIndex.sample_points(utm_pts)
backend/core/band.py
AGL Band Calculator
For each flight leg, samples the terrain at a fixed interval and returns the floor (peak terrain + min AGL) and ceiling (lowest terrain + max AGL) constraints.
  • compute_band(leg, terrain, params)
backend/core/safety.py
Safety Checker
Runs three vectorised checks on the final dense route: vertical clearance (hard), horizontal bubble (hard), and camera range (soft). Returns structured Violation objects.
  • check_route_safety(waypoints, utm_pts, vertical_terrain, bubble_terrain, camera_terrain, params)
backend/core/battery.py
Battery Model
Estimates total energy consumption and flight time using a physics model (hover power + horizontal power as a function of drone weight, speed, and air density).
  • estimate_battery(waypoints, params)
backend/core/geometry.py
Geometry Utilities
Polygon clipping (Sutherland-Hodgman), area computation, centroid, and convex-hull helpers used by the scan pattern generator and coverage statistics.
  • clip_polygon(subject, clip)
  • polygon_area_m2(polygon_utm)
backend/core/utm_utils.py · types.py
Shared Utilities
utm_utils: LatLon ↔ UTM conversion (wraps the utm package). types: shared dataclasses — Waypoint3D, LatLon, Violation, FlightParams, ViolationTier.
  • latlon_to_utm(lat, lon)
  • utm_to_latlon(e, n, zone_str)

Export Layer — backend/export/

backend/export/packager.py
ZIP Packager
Calls every renderer in sequence and assembles their outputs into a single in-memory ZIP, returned as the HTTP response body.
  • build_zip(waypoints, meta, ...)
backend/export/render_combined.py
Combined HTML Report
Assembles the interactive HTML mission report: inlines the 2-D Folium map, 3-D Plotly terrain view, and altitude profile into a single self-contained file.
  • render_combined_report(...)
backend/export/render_profile.py
Altitude Profile Chart
Produces a Plotly HTML chart showing the terrain surface, AGL band, drone flight path, and colour-coded violation markers. Hover shows AGL at each point.
  • render_profile(waypoints, terrain, violations)
backend/export/render_pdf.py
PDF Report
Generates a multi-page PDF using fpdf2. Includes: summary stats table, coverage breakdown, three separate violation tables (Safety / Scan / Transit), and embedded Matplotlib charts.
  • render_pdf(plan_meta, waypoints, ...)
  • FlyHighPDF.violation_table(violations)
  • FlyHighPDF.section_title(text)
backend/export/render_map.py · render_3d.py · render_kml.py
Map / 3D / KML Renders
render_map: Folium 2-D interactive map with route and violation markers. render_3d: Plotly 3-D terrain mesh with drone path. render_kml: KML file importable into Google Earth.
  • render_map(waypoints, violations)
  • render_3d(waypoints, terrain)
  • render_kml(waypoints)
backend/export/waypoints.py · mission_log.py
Waypoints & Log
waypoints: Serialises the final Waypoint3D list to JSON and CSV formats. mission_log: Writes a human-readable text log with statistics, warnings, and violation summaries.
  • waypoints_to_json(waypoints)
  • build_mission_log(meta, violations)

Frontend — React + MUI + Leaflet

frontend/src/App.tsx
App Shell
Top-level component. Owns the mission state, plan results, violation filter toggles, and terrain session. Composes the map, sidebar, and modals. Mounted at /missions/:folder.
  • useMissionState()
  • usePlanRoute()
  • violationFilters state
frontend/src/components/map/
Map Layer
Leaflet map with drawing tools. MapCanvas is the container. MapMarkers draws start/POI/waypoint pins. MapRoute draws the planned path. MapViolationLayer draws colour-coded "!" violation markers (Safety=red, Scan=orange, Transit=yellow).
  • MapCanvas → MapMarkers
  • MapCanvas → MapRoute
  • MapCanvas → MapViolationLayer
  • makeViolationIcon(category)
frontend/src/components/sidebar/
Sidebar Tabs
Three-tab sidebar: Mission (point list, POI configuration), Config (flight parameters, drone presets), Results (violations, download, PDF export). LiveEstimatesBar shows pre-plan battery/time estimates in real time.
  • SidebarShell → MissionTab
  • SidebarShell → ConfigTab
  • SidebarShell → ResultsTab
  • LiveEstimatesBar (useLiveEstimates)
frontend/src/hooks/
Custom Hooks
All stateful logic lives in hooks, not components. useMissionState manages the point list. usePlanRoute fires the POST /plan request and parses the response. useDraftPersistence auto-saves to localStorage. useUndoRedo wraps any state with history.
  • useMissionState()
  • usePlanRoute(session, state)
  • useLiveEstimates(state)
  • useDraftPersistence(folder, state)
frontend/src/api/index.ts
API Client
All HTTP calls to the backend are centralised here. Each function maps to one API endpoint. Returns typed responses or throws on error. Used by hooks, not directly by components.
  • planRoute(request)
  • uploadTerrain(files, types)
  • getMission(folder)
  • saveMission(folder, state)
  • generatePdf(meta)
frontend/src/components/ResultsPanel.tsx
Results Panel
Displays flight stats, battery usage, and the violation list grouped by category (Safety / Scan / Transit). Three chip toggles control which violation categories are shown on the Leaflet map.
  • violationFilters prop
